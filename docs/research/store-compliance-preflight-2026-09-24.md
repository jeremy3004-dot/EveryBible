# Store compliance preflight: iOS 1.0.9 (build ≥448) and next Android release

Date: 2026-09-24. Branch `hardening/compliance`, based on `fb897825`.
Scope: App Store Review Guidelines and ASC upload checks (ITMS-\*), plus Google Play policy, for the
code that ships tonight. Checked read-only against the repo; nothing was sent to App Store Connect,
Play Console, Supabase or any other live service.

## How the native projects are managed

- **iOS is committed, not generated.** `ios/EveryBible/**`, `project.pbxproj`, `Podfile(.lock)` are
  tracked (`.gitignore:41-57`), and `iosNativeConfig.test.ts` already records that prebuild does
  not run for iOS. `eas build --local` therefore ships the committed `Info.plist`,
  `PrivacyInfo.xcprivacy` and `InfoPlist.strings`. `app.json` only matters for iOS if someone runs
  prebuild again.
- **Android uses CNG.** `/android` is ignored (`.gitignore:58`). CI runs prebuild and then
  `eas build --local` (`.github/workflows/android-production-release.yml`), so Android's manifest
  comes from `app.json` + the prebuild template + library manifests merged at build time. The
  Android findings below come from a throwaway `npx expo prebuild --platform android --no-install`
  in a scratch copy (deleted afterwards).

## Proposed App Store privacy label (owner updates ASC)

Tracking: **No** (no data is used for tracking or shared with data brokers or ad networks).

**Data Linked to You**

| Apple category | Type                                                                          | Purposes          |
| -------------- | ----------------------------------------------------------------------------- | ----------------- |
| Contact Info   | Name, Email Address                                                           | App Functionality |
| User Content   | Photos or Videos (optional avatar)                                            | App Functionality |
| User Content   | Audio Data (optional feedback voice notes)                                    | App Functionality |
| User Content   | Other User Content (feedback comments; later prayer requests and group notes) | App Functionality |
| Identifiers    | User ID                                                                       | App Functionality |
| Usage Data     | Product Interaction                                                           | Analytics         |
| Location       | Coarse Location                                                               | Analytics         |

**Data Not Linked to You**

| Apple category | Type                                                             | Purposes          |
| -------------- | ---------------------------------------------------------------- | ----------------- |
| Diagnostics    | Crash Data                                                       | App Functionality |
| Diagnostics    | Other Diagnostic Data (handled errors, audio/text-pack failures) | App Functionality |
| Usage Data     | Product Interaction (signed-out users)                           | Analytics         |
| Location       | Coarse Location (signed-out users)                               | Analytics         |

Note: in ASC, a type that is linked for some users is declared once as **linked**. The "not linked"
rows for usage and location are shown for completeness only.

Owner decisions:

- **Identifiers → Device ID.** The random crash-report install id and the push token are app-scoped,
  not device-level. Leaving them undeclared is defensible. Declaring Device ID (not linked, App
  Functionality) is the conservative choice.
- **Sensitive Info (religious beliefs).** Nothing in 1.0.9 asks for beliefs. Revisit before the prayer
  wall ships, because prayer requests can reveal religious beliefs.
- `PrivacyInfo.xcprivacy` `NSPrivacyCollectedDataTypes` is empty. It isn't enforced at upload, but it
  can be filled in to match the label above (both `app.json` and the committed file; the test keeps
  them in sync).

## Proposed Google Play Data safety mapping

Collected, not shared (service providers are not "sharing"). Encrypted in transit: **yes**. Users can
request deletion: **yes** (in-app, and a web URL is required, see the actions below).

| Play category            | Type                                         | Required/optional     | Purposes                              |
| ------------------------ | -------------------------------------------- | --------------------- | ------------------------------------- |
| Location                 | Approximate location                         | Required (no opt-out) | Analytics                             |
| Personal info            | Name, Email address, User IDs                | Optional (sign-in)    | Account management, App functionality |
| Photos and videos        | Photos                                       | Optional              | App functionality                     |
| Audio                    | Voice or sound recordings                    | Optional              | App functionality                     |
| App activity             | App interactions                             | Required              | Analytics                             |
| App activity             | Other user-generated content                 | Optional              | App functionality                     |
| App info and performance | Crash logs, Diagnostics                      | Required              | App functionality                     |
| Device or other IDs      | Device or other IDs (install id, push token) | Required              | App functionality                     |

## Proposed privacy-policy wording (for counsel/owner; not applied)

Suggested additions to `apps/site/app/privacy/page.tsx` (and `legal/privacy.html` if it is still
served):

> **Crash and error reports.** When the app crashes or hits an error, it sends us a diagnostic
> report: the error type, a shortened error message with links, email addresses and codes removed,
> the screen you were on, your device's operating system and app version, and a random identifier
> created for this installation. Reports are not linked to your account and are deleted after
> 90 days.

> **Approximate location.** We use your IP address to estimate your approximate location (country,
> region, city, to about 10 km) for aggregate usage statistics. We do not use GPS or collect precise
> location.

> **Voice recordings.** If you choose to record an audio response to a chapter, the recording is
> stored with your feedback so translation teams can review it. It is deleted when you delete your
> account.

> **Notifications.** If you allow notifications, we store your device's push token to send the
> reminders and updates you have turned on.

> **Deleting your account.** You can delete your account in the app under More → Settings → Delete
> Account, or by emailing us. Deletion removes your account, profile, synced data, profile photo and
> voice recordings. Feedback you gave on Bible translations may be kept without your name or any
> other link to you.
