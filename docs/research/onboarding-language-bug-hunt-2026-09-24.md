# Onboarding and language-flow bug hunt (2026-09-24)

This hunt covered first-run onboarding (`LocaleSetupFlow`), device-locale detection, switching
the interface language in the app, RTL, the first translation download, the Every Language
and Supabase catalog failing or being offline, the re-run of onboarding after sign-out,
phantom bundled translations, plural and number formatting on Hermes, and startup-path cost.

Nothing here was run on a device or simulator. Every finding comes from reading the code and
from Node tests.

## Fixed (test-first, one commit each)

## Found, not fixed

- **Low (copy):** On a catalog failure or offline first run, the error card reads "Something went wrong" with `onboarding.noLanguagesFoundBody`, which is advice about search spelling. It should say the connection failed and that the listed Bibles work offline. This needs a new key in all 21 locales.
- **Low (copy):** When the first translation download fails, onboarding and the picker both show `bible.failedToLoad` ("We could not load this chapter right now"). That text is about chapters, not a failed download.
- **Low:** While one onboarding row is downloading, the other rows stay tappable. The store dedupes only by id, so two downloads can race and each calls `completeInitialSetup`.
- **Low (perf):** `buildInitialOnboardingLanguageOptions` still calls `localeCompare`, which is slow on Hermes, for every debounced keystroke (per-group sort, label check, final sort). One lazily created `Intl.Collator` would cut that cost. This path is not module-eval or hydration.
- **Product decision:** `zh-Hant`/`zh-TW` devices get the Simplified Chinese interface, and `sr-Latn`/`he`/`fa` devices fall back to English (no locale exists). Arabic and Urdu text renders in an LTR layout by design (`rtlPolicy`), so switching language never needs a restart. The app does not currently tell users about this.
- `services/progress/readingActivity.ts:60` formats dates with the device locale (`undefined`) rather than the app language.

## Checked and fine

- **Plurals on Hermes:** `pluralRulesPolyfill` is installed before `i18n.init`. It covers all 21 locales and is checked against ICU. i18next's other `Intl` calls are wrapped in try/catch. `Intl.DisplayNames` is feature-detected.
- **Dates and numbers:** they use `Intl.DateTimeFormat`/`toLocale*String` with the app language, and Hermes provides both.
- **Offline or catalog failure during onboarding:** after a 7 s timeout the bundled BSB, WEB, ASV and NPIULB remain selectable, and there is a retry button. If the hydration finishes late, it clears the error.
- **Skipping onboarding:** there is no skip. The first run requires choosing a Bible, and that works offline.
- **Startup path:** no new synchronous `Intl`, `new URL`, or `JSON.parse` of large data was added. The only new startup work is a string map over `getLocales()`, and one extra field read in the existing MMKV language parse.
